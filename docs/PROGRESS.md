## ทำเกินแผน (ไม่มีในคู่มือ แต่มาจาก pain point จริง)

บุคลิกและชื่อเล่น "แงว" ระดับองค์กร · ความจำบทสนทนา 20 ข้อความต่อแชท · ความต่อเนื่องข้ามแชท ·
DM ตอบโดยไม่ต้องแท็ก · เอ่ยชื่อแล้วโมเดลตัดสินใจเองว่าจะตอบหรือเงียบ · อ่านรูปภาพ ·
ตั้งเตือนตามเวลา · ADMIN จัดการพนักงานผ่านแชท · ดึงชื่อกลุ่มจาก LINE อัตโนมัติ ·
**อ่านไฟล์เอกสาร PDF / Word / Excel / CSV / ข้อความ** · ตอบแบบอ้างข้อความต้นทางในกลุ่ม (quoteToken) ·
**ชุดข้อสอบอัตโนมัติ 13 ข้อ + ชุดทดสอบตัวตัดสินอีก 8 ข้อ** (กันบั๊กเดิมกลับมา รันทุกครั้งที่ push) ·
**Admin Console** หน้าเว็บสำหรับ ADMIN · **คุยต่อในกลุ่มได้โดยไม่ต้องแท็กซ้ำ**

## ✅ ปัญหา API key — แก้แล้ว (1 ก.ย. 2026 ช่วงดึก)

บอทเคยตอบ "ขอโทษค่า ระบบขัดข้องชั่วคราว" ทุกข้อความ เพราะ Anthropic API ฟ้องว่าเครดิตไม่พอ
ทั้งที่หน้า Billing มีเงินอยู่ **สาเหตุจริงคือตัว API key เอง ไม่ใช่เครดิต** เปลี่ยนเป็น key แบบ
organization (ไม่ผูก workspace) แล้วใช้ได้ทันที

ยืนยันแล้วว่ากลับมาจริง — คุยกับบอทใน LINE ได้ตอน 17:10 UTC และ `token_usage` บันทึกครบทุกคำตอบ
รายละเอียดและลำดับการไล่ปัญหาถ้าอาการกลับมา อยู่ใน [docs/HANDOFF.md](HANDOFF.md)

key เก่าที่หลุดในภาพหน้าจอ เพิกถอนแล้วเมื่อ 2 ก.ย. 2026

## ค้างอยู่ / ต้องทำต่อ

1. เฝ้าดูอัตราการเผาเครดิต — ดูจากแท็บ "ภาพรวม" ใน Admin Console
   ทั้งวันที่ 2 ก.ย. ใช้ไป $4.31 แต่ **$3.42 เป็นค่ารันข้อสอบ ค่าคุยจริงแค่ $0.89**
   แก้แล้วด้วยการให้ push ใช้ haiku (ดู HANDOFF) ยังต้องดูอีก 2-3 วันถึงจะรู้อัตราจริง
2. MVP 0.3 ที่เหลือ: สรุปความรู้ข้ามกลุ่ม และทำดัชนีเอกสารที่ส่งเข้ามา (ควรรอข้อมูลจริงสะสมก่อน)
   `extract_events` เรียกโมเดลสำเร็จครั้งแรกเมื่อ 2 ก.ย. — ท่อเริ่มไหลแล้ว รอ events สะสม

หมายเหตุ: "แพรว" เป็นพนักงานสมมติที่ใช้ตอนทดสอบ ปิดใช้งานแล้ว (`is_active = false`) ไม่ต้องผูกบัญชี
ส่วนพนักงานจริงในระบบตอนนี้คือ ตั้ม (ADMIN), XXXXXX (MANAGER), FA (EMPLOYEE)

**อย่าพยายามลบแถว "แพรว" ทิ้ง** — ตัดสินใจแล้วว่าเก็บไว้แบบปิดใช้งาน มี tasks 2 รายการ (ปิดจบทั้งคู่)
และ audit_log 1 แถวอ้างถึงอยู่ FK ทุกตัวเป็น `NO ACTION` จะลบได้ต้องทำลาย audit trail ก่อน ซึ่งไม่คุ้ม
โค้ดกรอง `is_active = true` ทุกจุดที่ดึงรายชื่ออยู่แล้ว ผลลัพธ์จึงเท่ากับถูกลบ

เสร็จแล้วในรอบนี้: deploy tool events, เพิ่มข้อสอบ events 3 ข้อ, เก็บกวาด events ใน `runEval`,
ตั้ง XXXXXX เป็น MANAGER, ใส่ CRON_SECRET เป็น repository secret, ย้ายมา deploy ด้วย Supabase CLI

เสร็จแล้วรอบ 2 ก.ย. (ย้ายมาเครื่อง Mac): clone repo + link Supabase project, เปลี่ยน `ANTHROPIC_API_KEY`
เป็นแบบ org-level ทำให้บอทกลับมาใช้งานได้, เพิกถอน key เก่าที่หลุด, ลง PowerShell ผ่าน
`brew install powershell` เพื่อให้รันข้อสอบบน Mac ได้, `deno check` ผ่านทั้งสองฟังก์ชัน,
**เอาบอทเข้ากลุ่มงานจริงและทีมเพิ่ม OA เป็นเพื่อนแล้ว** — เริ่มเก็บข้อมูลจริงได้

ยืนยันหลังเปลี่ยน key: **ข้อสอบผ่าน 11/11 ด้วย sonnet** และ **prompt caching ทำงานจริง**
(ราว 6 ใน 10 ของ token มาจาก cache ไม่โดนคิดราคาเต็ม)

หมายเหตุ: สั่งรันข้อสอบบน GitHub Actions ได้โดยไม่ต้องใช้ค่า `CRON_SECRET` ในเครื่อง
เพราะ workflow ดึงจาก repository secret เอง — `gh workflow run agent-eval.yml --ref main`

เพิ่มรอบ 2 ก.ย. (ต่อ): ลดประวัติบทสนทนาเหลือ 20 ข้อความ, แยกกฎห้าม markdown ออกมาให้ชัด,
**สร้าง Admin Console** (หน้าเว็บบน GitHub Pages + edge function `admin-console` + tool `create_admin_link`),
บอกทางลัด scope ให้ 3 tools ที่พังในแชทส่วนตัว, **ทำโหมดคุยต่อโดยไม่ต้องแท็กให้เสร็จ**
(เรียกชื่อล้วน ๆ ตอบทันที + บอทพูดล่าสุดภายใน 3 นาทีให้ตัวตัดสินอ่านต่อ) พร้อมชุดทดสอบตัวตัดสิน 8 เคส,
ให้ push ใช้ haiku เป็นด่านคัดกรองแทน sonnet หลังพบว่าค่าทดสอบแพงกว่าค่าใช้งานจริง 4 เท่า
