## อ่านแค่หน้านี้ก็ดูแลแงวได้ (ไม่ต้องรู้โค้ด)

แงวคือบอทในไลน์ ข้างในมันคือ "สมอง" ที่เช่ามาจากบริษัท AI อีกที เราสลับสมองได้
โดยไม่ต้องแก้โค้ด แค่เปลี่ยนค่าในหน้าตั้งค่าเดียว

**ตอนนี้ใช้สมองอะไรอยู่**

| ส่วน | ใช้อะไร | ราคาต่อครั้ง |
|---|---|---|
| ตอบแชทในไลน์ | Gemini 3.7 Flash ของ Google | ~$0.006 ต่อข้อความ (≈ 0.21 บาท) |
| สรุปประจำวัน/สัปดาห์ และการอ่านแชทจับงานเอง | Gemini 3.7 Flash | ~$0.0006 ต่อกลุ่ม |
| ตัวสำรองเวลาตัวหลักล่ม | GPT-5.6 Luna ของ OpenAI | สลับเองอัตโนมัติ |

### สวิตช์ทั้งหมดอยู่ที่เดียว

เข้า Supabase → เมนู Edge Functions → Secrets แล้วแก้ค่าตามตาราง
ไม่ต้อง deploy ไม่ต้องรันคำสั่งอะไร มีผลกับข้อความถัดไปทันที

| ชื่อค่า | ใส่อะไรได้ | แปลว่า |
|---|---|---|
| `CHAT_MODEL` | `gemini-flash` · `luna` · `sonnet` · `haiku` | สมองที่ใช้ตอบแชท |
| `JOBS_MODEL` | เหมือนกัน | สมองที่ใช้ทำงานเบื้องหลัง |
| `CHAT_FALLBACK_MODEL` | เหมือนกัน หรือ `none` | สมองสำรองเวลาตัวหลักล่ม (`none` = ไม่ต้องมีสำรอง) |
| `JOB_ONLY_GROUPS` | ชื่อกลุ่มคั่นด้วยจุลภาค เช่น `AA1,AA2` | ให้งานเบื้องหลังทำเฉพาะกลุ่มที่ระบุ **ใช้ตอนทดสอบเท่านั้น ลบทิ้งหลังทดสอบเสร็จ** |
| `GEMINI_THINKING_LEVEL` | `low` (ตั้งไว้) หรือลบทิ้ง | ให้ Gemini คิดน้อยลงก่อนตอบ ประหยัดราว 30% ผ่านข้อสอบครบทั้งชุดปกติและชุดยาก ถ้าสงสัยว่าตอบโง่ลงให้ลบค่านี้แล้วเทียบ |

| ส่ง PDF แล้วบอทบอกว่าอ่านไม่ได้ | สมองที่ใช้อยู่อ่านไฟล์ไม่เป็น | เปลี่ยน `CHAT_MODEL` กลับเป็น `gemini-flash` |
| สรุปตอนเย็นไม่มา | งานเบื้องหลังพัง | เช็ค `JOBS_MODEL` ว่ายังตั้งถูก และ `JOB_ONLY_GROUPS` ต้องไม่มีค่าค้างอยู่ |

## ประหยัดเงิน — สิ่งที่ทำไปแล้วและวัดผลได้ (3 ก.ย. 2569)

วัดด้วยข้อสอบชุดกันของเก่าพัง 13 ข้อเดิมทุกครั้ง ผ่าน 13/13 ทุกรอบ

| ขั้น | input เต็มราคา/คำตอบ | อ่านจาก cache | บาท/คำตอบ |
|---|---|---|---|
| ตั้งต้น (นับ token ที่ใช้คิดถูกต้องแล้ว) | 20,988 | 312 | 0.64 |
| ตัดหางประวัติแชทที่ 400 ตัวอักษร | 14,100 | 1,237 | 0.46 |
| cache แบบสั่งเอง (กฎ + เครื่องมือ) | 6,726 | 10,275 | 0.29 |
| ระดับการคิด `low` | 4,924 | 9,070 | **0.21** |

รวมแล้วถูกลง **3 เท่า** จากตอนเช้า และถูกกว่า sonnet เดิม (0.99 บาท/คำตอบ) เกือบ 5 เท่า

**cache แบบสั่งเอง** ฝากกฎ + คำอธิบายเครื่องมือทั้ง 22 ตัว (~5 พัน token) ไว้ฝั่ง Google ก้อนเดียว
แล้วอ้างชื่อทุกคำขอ อ่านจาก cache คิดเงิน 1 ใน 10 ของราคาเต็ม

- ชื่อก้อนเก็บใน `org_settings` คีย์ `gemini_cache:chat` ให้ทุก instance ใช้ก้อนเดียวกัน
- อายุ 4 ชั่วโมง หมดแล้วสร้างใหม่เอง ค่าเก็บราว $0.01 ต่อก้อน ไม่มีนัย
- แก้กฎหรือเพิ่ม tool เมื่อไร ลายนิ้วมือเปลี่ยน ก้อนเก่าถูกทิ้งเอง ไม่ต้องล้างมือ
- สร้างไม่ได้หรือ Google ทำก้อนหาย → ส่งแบบเต็มราคาแทนโดยอัตโนมัติ บอทไม่พังเพราะเรื่องประหยัด
- cache อัตโนมัติของ Gemini วัดแล้ว**ไม่ติด**กับรูปแบบคำขอของเรา จึงต้องสั่งเอง

**สิ่งที่ลองแล้วไม่ช่วย** แยก system prompt เป็นส่วนนิ่ง/ส่วนเปลี่ยนเพื่อหวังพึ่ง cache อัตโนมัติ — ตัวเลขไม่ขยับเลย
โค้ดส่วนนั้นเก็บไว้เพราะ cache แบบสั่งเองต้องใช้ แต่ลำพังมันไม่ได้ลดเงิน

**ที่ยังไม่ได้แตะ** คำอธิบายเครื่องมือ 22 ตัวยาวและเป็นก้อนใหญ่สุดใน cache — ย่อได้แต่เสี่ยงเรื่องเลือก tool ผิด
ต้องวัดด้วยชุดยากถ้าจะทำ

## Gemini บล็อก prompt ทิ้ง — สิ่งที่รู้แล้ว (3 ก.ย. 2569)

Gemini ปฏิเสธคำขอบางชุดตั้งแต่ยังไม่เริ่มตอบ ตอบ 200 กลับมาโดยไม่มี candidates
มีแต่ `promptFeedback.blockReason = PROHIBITED_CONTENT` ตอนแรกบอทแปลงความว่างนั้น
เป็น `…` ส่งให้ผู้ใช้ ตอนนี้จับแยกเป็น error ชื่อ `PromptBlocked` แล้ว

**ปิด filter ตัวนี้ไม่ได้** `safetySettings` คุมได้เฉพาะหมวด `HARM_CATEGORY_*`
ซึ่งจะขึ้น `blockReason = SAFETY` ส่วน `PROHIBITED_CONTENT` เป็นคนละตัวและผู้เรียกสั่งไม่ได้
ทางเดียวคือเปลี่ยนสิ่งที่ส่งไป

**สิ่งที่ทดสอบแล้วและตัดออกได้**

| ทดสอบ | ผล |
|---|---|
| ยิงข้อความผู้ต้องสงสัยทีละอันในแชทที่ไม่มีประวัติ (10 แบบ รวมชื่อไฟล์เต็มและท่อนที่พูดถึงเด็ก) | ผ่านหมด |
| ยิงประวัติทีละบรรทัด ทั้ง 21 บรรทัด | ไม่มีบรรทัดไหนโดนเดี่ยว ๆ |
| ประวัติทั้งก้อน + system ชุดจริง + tool ครบ 22 ตัว | ผ่าน |
| ยิงชุดเดิมซ้ำ 5 ครั้ง | ไม่โดนสักครั้ง |

**สิ่งที่หลักฐานชี้** ตอนที่โดนจริง (02:10–02:14 UTC, 11 ครั้ง) prompt มี "บริบทข้ามแชท"
อยู่ด้วยพร้อมกับประวัติในแชทนั้น พอ retry โดยตัดประวัติออกก็ผ่านทันทีทั้ง 8 ครั้ง
และตอนไล่หาทีหลัง บริบทข้ามแชทหมดอายุ 6 ชั่วโมงไปแล้ว (เหลือ 0 ตัวอักษร) จึงผ่านหมดทุกชุด

สรุปเท่าที่พิสูจน์ได้: **ต้องมีทั้งบริบทข้ามแชทและประวัติในแชทพร้อมกันถึงจะโดน**
ขาดอย่างใดอย่างหนึ่งผ่านทั้งคู่ ยังยืนยันซ้ำไม่ได้เพราะบริบทข้ามแชทหมดอายุไปก่อน
ถ้าเจออีกให้รีบไล่ภายใน 6 ชั่วโมง — โหมดวินิจฉัยที่ใช้ตอนนั้นย้อนดูได้จาก git
(`__probe_history__` ใน commit ช่วง 3 ก.ย.)

**สิ่งที่บอททำตอนโดน** ถอยทีละขั้นแทนที่จะทิ้งทุกอย่าง: ตัดบริบทข้ามแชทก่อน
เพราะเป็นของนอกห้องและมีค่าน้อยที่สุด ถ้ายังโดนค่อยตัดประวัติในแชทนี้ออก
ลำดับนี้สำคัญ เพราะประวัติคือสิ่งที่ทำให้คำสั่งต่อเนื่องอย่าง "เอาอันแรก" ยังทำงานได้

## โมเดลที่ตอบแชทจริง (อัปเดต 3 ก.ย. 2569)

ตั้งด้วย secret `CHAT_MODEL` ที่ Supabase → Edge Functions → Secrets ใส่ชื่อย่อเดียวกับที่ข้อสอบใช้
(`gemini-flash` · `luna` · `sonnet` · `haiku`) อ่านใหม่ทุก request จึงย้ายหรือถอยกลับได้
**ด้วยการแก้ secret อย่างเดียว ไม่ต้อง deploy**

ตอนนี้ตั้งเป็น `gemini-flash` ถ้าจะถอยกลับ

```bash
npx supabase secrets set CHAT_MODEL=sonnet
```

ถ้า `CHAT_MODEL` ว่าง ตั้งผิด หรือ secret ของค่ายนั้นหาย บอทจะตกกลับมาใช้ `claude-sonnet-5`
แล้วเขียน error ลง log แทนที่จะเงียบใส่ทีม — บอทที่ตอบด้วยโมเดลสำรองยังใช้งานได้
บอทที่ไม่ตอบเลยคือของเสีย

**สิ่งที่หายไปเมื่อไม่ได้ใช้ Anthropic** อ่านไฟล์ PDF ที่ส่งเข้าแชทตรง ๆ ไม่ได้ (Word/Excel/CSV/ข้อความ
ยังอ่านได้ตามเดิม เพราะแปลงเป็นข้อความก่อนอยู่แล้ว) บอทจะบอกผู้ใช้ว่าอ่าน PDF ไม่ได้
แล้วขอให้ก็อปข้อความมาวางแทน ไม่ใช่เงียบ ๆ ทิ้งไฟล์แล้วเดาเนื้อหา
และ prompt caching ใช้ไม่ได้ ต้นทุนต่อข้อความจึงยังไม่รู้จนกว่าจะเก็บตัวเลขจริงได้สักวัน

**งานเบื้องหลังยังเป็น Claude ทั้งหมด** สรุปรายวัน/รายสัปดาห์ และการอ่านบทสนทนาจับงานทุก 3 ชม.
อยู่ใน `scheduled-jobs` ซึ่งเรียก Anthropic SDK ตรง ๆ ไม่ผ่านตัวแปลข้ามค่าย

https://korrakottum-code.github.io/MT-Agent-1/ — ทำสิ่งที่ทำในแชทได้อยู่แล้ว แต่ทีละหลายรายการได้เร็วกว่า

**วิธีเข้า** พิมพ์ในแชทว่า `ขอลิงก์ console` (ต้องเป็น ADMIN) บอทจะ DM ลิงก์ให้
ใช้ได้ครั้งเดียวภายใน 15 นาที เปิดแล้วอยู่ได้ 8 ชั่วโมง

**ทำไมหน้าเว็บไม่ได้อยู่กับ API** — Supabase เขียนทับ `content-type: text/html` เป็น `text/plain`
พร้อมใส่ `nosniff` บนโดเมน `*.supabase.co/functions/v1/*` (กันเอาโดเมนไปโฮสต์หน้าหลอกลวง)
เบราว์เซอร์จึงแสดงเป็นข้อความดิบ ส่วน `application/json` ผ่านปกติ — API จึงยังอยู่ที่ Supabase ได้
**อย่าเสียเวลาลองย้ายหน้าเว็บกลับไปที่ Edge Function มันไม่มีทางเรนเดอร์ได้** เว้นแต่จะซื้อ custom domain

**ทำไมไม่ใช้คุกกี้** — หน้าเว็บคนละโดเมนกับ API คุกกี้จึงเป็น third-party ซึ่ง Safari บล็อกโดยปริยาย
ใช้ bearer token ที่ส่งต่อทาง URL fragment (`#s=...`) แทน — fragment ไม่ถูกส่งไปเซิร์ฟเวอร์
จึงไม่โผล่ใน log ของ GitHub และไม่ติดไปกับ Referer หน้าเว็บย้ายเข้า sessionStorage แล้วล้าง URL ทันที
ผลพลอยได้คือ CSRF ทำไม่ได้เลย เพราะไม่มี credential ที่เบราว์เซอร์แนบให้เอง

**ด่านความปลอดภัย** — เก็บเฉพาะ SHA-256 ของ token · ขอลิงก์ใหม่จะเพิกถอนลิงก์เก่าที่ยังไม่ถูกใช้ ·
อ่าน role สดทุก request (ถอด ADMIN แล้ว session ตายทันที) · ไม่คืนตัวลิงก์ให้โมเดล กันมันพิมพ์ซ้ำลงกลุ่ม ·
ทุกการกระทำลง `audit_logs` · ปิดใช้งาน/ลดสิทธิ์ตัวเองไม่ได้ กัน ADMIN คนสุดท้ายล็อกตัวเองออก

หน้าเว็บอยู่ที่ `web/index.html` deploy ขึ้น GitHub Pages อัตโนมัติเมื่อ push
ในนั้นไม่มีความลับ มีแต่โค้ดหน้าจอ ทุกสิทธิ์ตรวจที่ฝั่ง API

## ดูว่าเงินหมดไปกับอะไร

ทุกครั้งที่เรียกโมเดลจะถูกบันทึกลงตาราง `token_usage` พร้อมบอกว่าเป็นงานประเภทไหน
(`chat` = คุยกับทีม, `eval` = รันข้อสอบ, `daily_summary` / `weekly_summary` / `extract_events` = งานตามเวลา)

```sql
select purpose,
       count(*) as calls,
       sum(iterations) as model_requests,
       sum(input_tokens) as input,
       sum(output_tokens) as output,
       sum(cache_read_tokens) as cache_hits
from token_usage
where created_at > now() - interval '1 day'
group by purpose
order by input desc;
```

`iterations` คือจำนวนครั้งที่ยิงเข้าโมเดลเพื่อให้ได้คำตอบเดียว (คำตอบที่ต้องเรียก tool จะมากกว่า 1)
ถ้า `cache_hits` เป็น 0 ตลอดแปลว่ายังไม่ได้เปิด prompt caching — คำสั่งระบบกับคำอธิบาย tool
ถูกคิดเงินเต็มราคาซ้ำทุกครั้งทั้งที่เนื้อหาเหมือนเดิม

รายงานให้คะแนนแยกเป็น 3 แกน เพราะ "โมเดลไหนดีกว่า" จริง ๆ แล้วเป็นคนละคำถามกัน

| แกน | คือ | มาจากเคส |
|---|---|---|
| `correct` | ความถูกต้อง — ทำตามกฎ ไม่แต่งข้อมูล ไม่อ้างว่าทำสำเร็จทั้งที่ไม่ได้ทำ | เคส `cmp-*` ที่ติดป้าย `"dimension": "correct"` |
| `tools` | การเรียกใช้เครื่องมือ — หยิบ tool ถูกตัว และไม่แตะตัวที่ไม่ควรแตะ | เคส `cmp-*` ที่ติดป้าย `"dimension": "tools"` |
| `silence` | ตัดสินเองว่าข้อความในกลุ่มพูดกับมันหรือเปล่า | `cases-judge.json` ทั้งชุด |

ราคาไม่ใช่เคส แต่มาจากยอด token ที่ endpoint ส่งกลับมาทุกครั้ง คูณกับ `tests/prices.json`
ช่อง `cost/round` คือเงินที่เสียไปกับการรันข้อสอบชุดนี้ครบหนึ่งรอบบนโมเดลนั้น
ใช้เทียบสัดส่วนระหว่างโมเดลได้ ไม่ใช่ค่าใช้จ่ายรายวันของบอท

โมเดลที่ชนะไม่ครบทั้ง 3 แกนเป็นเรื่องปกติ ให้ชั่งตามงานจริง — ของบอทตัวนี้
`correct` กับ `tools` พลาดแล้วทีมเห็นทันทีและเสียความเชื่อถือ ส่วน `silence` พลาดแล้วน่ารำคาญ
แต่ไม่ทำให้ข้อมูลผิด

ชุดยาก `tests/cases-hard.json` แยกอีกไฟล์ ใช้ตอนที่โมเดลทำชุดปกติได้เต็มจนแยกกันไม่ออกแล้ว
เล็งเรื่องที่ชุดปกติไม่ได้แตะ: คำสั่งที่คนอื่นฝากมาบอกแทน · ผู้ใช้ยืนยันตัวเลขของตัวเองผิด ·
ขอสิ่งที่บอทไม่มีเครื่องมือให้ทำ · คำสั่งมีเงื่อนไขแล้วขั้นต่อไปต้องขออนุญาตก่อน ·
วันที่ที่ต้องบวกข้ามสัปดาห์ · ประโยคที่เอ่ยชื่อบอทแต่พูดกับคนอื่น

```bash
gh workflow run model-bakeoff.yml --ref main -f cases=tests/cases-hard.json
```

**อ่านผลยังไง** โมเดลไม่ deterministic รอบเดียวแทบไม่บอกอะไรเวลาคะแนนสูสี ใช้ `-Repeat 3`
ก่อนตัดสินใจอะไรจริงจัง แล้วดูช่องที่ขึ้น `FLAKY` เป็นพิเศษ — ผ่านบ้างไม่ผ่านบ้างในกฎเรื่องสิทธิ์
หรือการยืนยันก่อนลบ แย่กว่าตกทุกครั้ง เพราะมันจะหลุดตอนอยู่ในมือทีมจริง

**ค่าใช้จ่าย** 19 เคส x จำนวนโมเดล x `-Repeat` เป็นจำนวนครั้งที่ยิงเข้าโมเดลจริง
เทียบ 3 โมเดล `-Repeat 3` = 171 ครั้ง แพงกว่ารันข้อสอบปกติหลายเท่า สั่งทีเดียวให้จบ อย่ารันเล่น

### เชื่อมโมเดลค่ายอื่นเข้ามาเทียบ

โค้ดพร้อมแล้ว เหลือแค่ตั้ง secret ที่ Supabase Dashboard → Edge Functions → Secrets
(ที่เดียวกับ `ANTHROPIC_API_KEY`) ห้าม commit ลง repo เด็ดขาด

| โมเดล (`-Models`) | secret ที่ต้องตั้ง |
|---|---|
| `luna` | `OPENAI_API_KEY` + `EVAL_LUNA_MODEL` (ชื่อรุ่นจริง) |
| `gemini-flash` | `GEMINI_API_KEY` + `EVAL_GEMINI_MODEL` (ชื่อรุ่นจริง) |
| `haiku`, `sonnet` | ใช้ `ANTHROPIC_API_KEY` ที่มีอยู่แล้ว |

**ชื่อรุ่นไม่ฝังในโค้ดโดยตั้งใจ** ชื่อรุ่นเปลี่ยนบ่อยกว่าโค้ด และเดาผิดทีเดียวคือรันข้อสอบทั้งชุดทิ้ง
ถ้าค่ายไหนย้าย endpoint เปลี่ยนได้ที่ `EVAL_LUNA_BASE_URL` / `EVAL_GEMINI_BASE_URL` โดยไม่ต้องแก้โค้ด
ค่าตั้งต้นคือ `https://api.openai.com/v1` และ endpoint โหมด openai ของ Gemini

ขาดตัวไหน endpoint ตอบกลับมาตรง ๆ ว่าต้องตั้ง secret ชื่ออะไร ไม่ปล่อยให้ไปเจอ 401 เอาเอง
และ `run-compare.ps1` เห็นข้อความนั้นแล้วจะข้ามโมเดลนั้นทั้งชุด ไม่รันต่อจนเปลืองเงิน

**โมเดลที่ทีมใช้จริงไม่ถูกแตะ** `MODEL` ยังเป็น `claude-sonnet-5` เหมือนเดิม
ค่า `model` ที่ส่งมาเลือกโมเดลได้เฉพาะ request ที่ผ่าน `x-test-key` เท่านั้น

#### ข้างในทำงานยังไง

โมเดลนอกค่าย Anthropic คุยผ่านหน้าตาแบบ OpenAI chat completions ซึ่งเป็นภาษากลาง
ที่ทั้ง OpenAI และ Gemini รับได้ ตัวแปลอยู่ที่ `supabase/functions/line-webhook/openai-compat.ts`
แปลงคำขอไป-กลับให้ลูป tool เดิมไม่ต้องรู้ว่ากำลังคุยกับค่ายไหน — ทั้ง prompt, TOOLS ทั้ง 22 ตัว
และกฎทุกข้อจึงเป็นชุดเดียวกันทุกโมเดล ซึ่งเป็นเงื่อนไขที่ทำให้ผลเทียบมีความหมาย

จุดที่ต่างกันโดยธรรมชาติและแก้ไม่ได้ มีสองอย่าง ต้องเผื่อใจตอนอ่านผล

1. **prompt caching ใช้ได้เฉพาะฝั่ง Anthropic** `cache_control` ถูกตัดทิ้งตอนแปลง
   ตัวเลขต้นทุนของโมเดลค่ายอื่นจึงเป็นราคาเต็มทุก token — ปัจจุบัน cache กินสัดส่วน
   ราว 6 ใน 10 ของ token ฝั่ง Anthropic ถือว่าเทียบกันตรง ๆ ไม่ได้ทั้งหมด
2. **ไฟล์ PDF แนบตรงได้เฉพาะฝั่ง Anthropic** ถ้าเคสไหนแนบ PDF ตัวแปลจะโยน error ทันที
   ไม่ใช่เงียบ ๆ ทิ้งไฟล์แล้วปล่อยให้โมเดลตอบมั่ว (ข้อสอบชุดเทียบไม่มีเคสแบบนี้)

ตัวแปลมีข้อสอบของตัวเอง 15 ข้อ รันฟรี ไม่ยิงเข้าโมเดลจริง

```bash
npx deno@2 test --allow-env supabase/functions/line-webhook/
```

รันชุดนี้ทุกครั้งที่แตะ `openai-compat.ts` เพราะถ้าตัวแปลพัง ผลเทียบจะโกหกว่า
"โมเดลนี้เรียก tool ไม่เป็น" ทั้งที่เป็นความผิดของตัวแปลเอง

หลังเชื่อมแล้ว ราคาต่อ 1 ล้าน token ของโมเดลใหม่ต้องไปเติมใน `tests/prices.json`
ไม่งั้นช่องต้นทุนในรายงานจะขึ้น `-` (ตั้งใจให้เป็นแบบนั้น ดีกว่าเดาราคาแล้วตัดสินใจผิด)

## อาการเสียที่เจอบ่อยและวิธีไล่

**บอทตอบ "ขอโทษค่า ระบบขัดข้องชั่วคราว" กับทุกข้อความ** → เช็คเครดิต Anthropic ก่อนเป็นอย่างแรก
ยิงข้อสอบข้อเดียวแล้วอ่าน body ของ error จะเห็นสาเหตุจริง (runner จะขึ้นแค่ 500 เฉย ๆ)

```bash

```

ถ้าขึ้นว่า `credit balance is too low` **อย่าเพิ่งเชื่อว่าเงินหมด** เคสวันที่ 1 ก.ย. ขึ้น error นี้
ทั้งที่หน้า Billing มีเงินอยู่ และสาเหตุจริงคือตัว key เอง ลำดับที่ควรไล่:

2. ถ้ามีเงินแต่ยังฟ้อง → สร้าง key ใหม่แบบ **organization (ไม่ผูก workspace)** แล้วเปลี่ยน secret
3. ถ้ายังไม่หาย → ทดสอบที่ https://console.anthropic.com/workbench ซึ่งใช้เครดิตก้อนเดียวกัน
   โดยไม่ต้องใช้ key ถ้า Workbench ก็ฟ้องด้วยแปลว่าเป็นปัญหาฝั่งบัญชี ให้แจ้ง Anthropic support
   พร้อม request id (เช่น `req_011Ced4FVpsg4BnJGe7XYjP3`) และภาพหน้า Billing

ทุกกรณีโค้ดไม่ได้พังและไม่ต้อง deploy ใหม่ — เปลี่ยน secret แล้วมีผลทันที

**เงื่อนไขที่เกี่ยวกับข้อความของบอทเองไม่ทำงาน** → ระวัง `.neq()` ของ PostgREST กับคอลัมน์ที่เป็น NULL ได้
คำตอบของบอทเก็บ `line_message_id` เป็น NULL และ SQL ตีความ `NULL <> 'x'` เป็น NULL ไม่ใช่ true
แถวของบอทจึงถูกกรองทิ้งไปเงียบ ๆ (บั๊กนี้ทำให้ฟีเจอร์คุยต่อตายตั้งแต่ deploy วันแรก)
ถ้าต้องคัดแถวออกจากคอลัมน์ที่เป็น NULL ได้ ให้ดึงมาแล้วกรองในโค้ดแทน

**ข้อสอบตกเพราะคำตอบภาษาไทย** → ดูก่อนว่า regex ไปแมตช์รูปปฏิเสธหรือเปล่า
เช่น คำต้องห้าม "เป็นคนจริง" จะไปโดน "ไม่ได้เป็นคนจริง" ซึ่งเป็นคำตอบที่ถูก
คำต้องห้ามควรขึ้นต้นด้วยคำปฏิเสธเสมอ

## พฤติกรรมสำคัญที่ควรรู้ก่อนแก้โค้ด

- **การตอบ** (แก้ครั้งใหญ่ 2 ก.ย. 2026) — แชทส่วนตัวตอบทุกข้อความ ส่วนในกลุ่มมี 4 ทาง
  1. แท็ก `@ai` → ตอบทันที
  2. **ชื่อล้วน ๆ** ("แงว", "แงวๆ") → ตอบทันที ไม่ผ่านตัวตัดสิน เพราะเรียกชื่อคือเรียก
  3. เอ่ยชื่อปนกับข้อความอื่น → ตัวตัดสินอ่านบริบทแล้วเลือกตอบหรือ `SILENT`
  4. **บอทเป็นคนพูดล่าสุดและเพิ่งพูดไม่เกิน 3 นาที** → ตัวตัดสินเช่นกัน
     (`FOLLOW_UP_WINDOW_MS`) คนไม่แท็กซ้ำกลางบทสนทนา ทางนี้เลยจำเป็น
  ทาง 3 กับ 4 เสียค่าเรียกโมเดลทุกข้อความเพื่อตัดสิน จึงผูกทาง 4 ไว้กับ "บอทพูดล่าสุด"
  ไม่ใช่แค่ช่วงเวลา — มีคนอื่นพูดแทรกเมื่อไรโซ่ขาดทันที
- **ตอบแบบอ้างข้อความ**: ในกลุ่มบอทจะแนบ `quoteToken` ของข้อความต้นทาง คำตอบจึงโผล่เป็น reply ที่อ้างข้อความนั้น
  ในแชทส่วนตัวไม่แนบ เพราะมีบทสนทนาเดียวอยู่แล้ว
- **บทสนทนาเก่าเป็นบริบท ไม่ใช่คิวคำสั่ง** (กฎ 8.1): เคยเจอบั๊กว่าถามเรื่องอื่นแล้วบอทย้อนไปตั้งเตือนซ้ำจากข้อความเก่า
  แก้ทั้งที่ prompt และใส่การกันตั้งซ้ำใน `create_reminder` (ถ้ามีข้อความเดียวกันสถานะ PENDING ในแชทนั้นอยู่แล้ว จะไม่สร้างใหม่)
- **`messages.line_group_id`** ใช้เป็น chat id: กลุ่มเก็บ groupId, แชทส่วนตัวเก็บ userId ของคู่สนทนา
- **คำตอบของบอท** ถูกเก็บลง messages ด้วย โดยใช้ `line_user_id = 'bot'`
- **ความจำ** มี 2 ชั้น: ระยะสั้น (30 ข้อความล่าสุดต่อแชท ส่งเป็นบริบททุกครั้ง) และถาวร (`users.preferences` ต่อคน + `org_settings.bot_persona` ระดับองค์กร)
- **รูป**: DM ส่งรูปตรง ๆ ได้ / ในกลุ่มต้องส่งรูปก่อนแล้วแท็กถามถึง "รูป" ระบบจะดึงรูปล่าสุดภายใน 24 ชม.
- **Event Extraction**: job `extract_events` อ่านบทสนทนาในกลุ่ม (ไม่แตะแชทส่วนตัว) ทุก 3 ชม. แล้วจับ
  งาน/ข้อตกลง/กำหนดส่ง ลงตาราง `events` สถานะ NEW — **ไม่กลายเป็นงานจริงเองเด็ดขาด** ต้องมีคนยืนยัน
  ข้ามกลุ่มที่มีข้อความใหม่น้อยกว่า 3 ข้อความ, ตัดทิ้งของที่ confidence < 0.6, และไม่รับ due_at ที่เกิน ±5 ปี
  (เคยเจอโมเดลตอบเป็น พ.ศ. 2569 ทำให้กำหนดส่งเพี้ยนไป 543 ปี)
  ป้องกันจับซ้ำ 3 ชั้น: ส่งรายการที่เคยจับไปแล้ว + รายชื่องานที่มีในระบบ ไปบอกโมเดล และมี unique index
  `(chat_id, type, title)` เป็นด่านสุดท้าย — รายการที่ถูกปัดทิ้งแล้วจะไม่ถูกเสนอซ้ำ
- **ไฟล์เอกสาร** (ตั้งแต่ v22): PDF ส่งเข้าโมเดลตรง ๆ, Word อ่านด้วย `npm:mammoth`, Excel ด้วย `npm:xlsx`,
  ส่วน txt/md/csv/tsv/json/log อ่านเป็นข้อความ — จำกัด 8MB ต่อไฟล์ และตัดข้อความที่ 120,000 ตัวอักษร
  DM ส่งไฟล์ตรง ๆ ได้ / ในกลุ่มต้องส่งไฟล์ก่อนแล้วแท็กถามถึง "ไฟล์/เอกสาร/สรุปประชุม/รายงาน" ระบบจะดึงไฟล์ล่าสุดภายใน 7 วัน
